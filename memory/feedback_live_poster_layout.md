# 直播海报版式记忆

## 2026-07-13 460期海报排版规则

- 模板1-5标题框：左侧固定 `title_x=226`，只向右加宽，`title_max_width=2110`。目标是避免标题第二行只剩一个字；不得通过缩小字号解决。
- 介绍文案字号：默认 96，最小 96。后续没有用户明确要求，不压缩文案字号。
- 介绍文案内部间距：统一 `caption_item_gap_max=40`。图1-4、图5、图6都必须遵守同一视觉规则。
- 介绍文案内部间距必须小于标题到第一条文案的间隙，也必须小于最后一条文案到直播时间的间隙。
- 图1-4标题到介绍文案间隙不能贴得太近，必须和图5视觉一致。标题一行时定版 `title_caption_gap_min=90`；标题两行时定版 `title_caption_gap_min_two_lines=120`，避免两行标题后文案视觉上贴得太近。
- 发内容小分队复核海报时必须发完整6张，不得只发图1-5。若中途补发，必须明确以新版完整6张为准。

## 2026-07-20 462期课程群发送身份复盘

- 462期出现错误：226课程群三条消息（李菁通知、预告帖正文、学院海报）显示为范丽丽，而不是直播物料小助手。
- 根因：只核验了 PPT 制作群通知 sender 是 bot，未逐条核验 226课程群消息 sender；执行时课程群发送动作走了 user 身份。
- 修正规则：所有群消息发送后必须核验消息本身 sender，不只看命令返回的 `identity`。
- 验收标准：`sender.sender_type == "app"` 且 `sender.name == "直播物料小助手"`。
- 课程群、内容小分队、PPT制作群、团队大群全部适用；如果任何群消息显示为范丽丽或其他 user，暂停继续发群消息，列清楚已发/未发/待办并询问用户怎么处理。

- 定时任务验收标准不是“我写了任务”，而是：任务存在、已加载/可触发、到点后目标群确实收到 bot 发出的文字和学院海报。

## 2026-07-21 异常处理边界

- 用户明确要求“以后不要自作主张，多问我”。遇到是否重发、撤回、补发、跳过、继续等选择，不要替用户决定。
- 正确做法：先说明“发生了什么、已发了哪些、哪些还没发、下一步建议”，然后等用户确认。
- 不要把临时纠错策略写成会跳过必要步骤的新硬规则；暂停是为了避免扩大错误，不等于剩余流程自动作废。
